# M2 scalar, lexical scope and named-call slice

Verified on Kali Linux under WSL2, C11. This is a semantic C API, **not**
an executable compiler and not full M2.

## Entry points
`checker_init(&c, &parser)` and `checker_run(&c, root)` consume the
source-backed M1 AST. Error state is in `Checker.errors`, `message`,
and `at`. No morphology is read and no identifier bytes are normalized.
The caller keeps the source and AST arena alive.

## Checked
- Built-in `صحيح` (i64), `بايت` (u8), `منطقي` (bool).
- Duplicate declaration rejection within one lexical scope, shadowing in
  nested blocks, lookup for global and function-parameter bindings.
- All top-level function names share the namespace with global variables and
  constants. Duplicate functions and function/global name collisions fail.
  A function name is not a scalar value or a writable assignment target.
- Named function calls check exact parameter count and scalar types. Function
  signatures are collected before global initializers and function bodies,
  allowing forward calls, recursion and mutual recursion. Global variable
  initializers still see only earlier global variables; function bodies see
  all globals.
- Local bindings shadow function names: trying to call a local scalar fails.
  Function values, indirect calls and chained calls such as `f()()` fail.
- Void-returning calls are allowed as expression statements, never as values
  in initializers, assignment, operators, conditions, arguments or returns.
  A void function returns with bare `أرجع؛`.
- Immutable `ثابت`, assignment lvalues (simple identifiers only),
  initializers, return types and scalar operator constraints.
- No implicit `int`↔`byte`, `int`↔`bool` conversion.
- Conditions must be bool, arithmetic operands i64 and logical operands bool.

## Limits
This is intentionally a **narrow, fail-on-unsupported** checker. Pointer,
array, struct and string types, indirect calls, field access, indexing,
user-defined type layout and frame sizes are not implemented.
Missing-return checks are conservative: a non-void function is rejected when
some control-flow path can reach the end without returning. While loops alone
do not guarantee a return; constant conditions are not folded. Do not use
this API as a full language-acceptance gate for unsupported constructs. The freestanding `niyahparse --check FILE`
now invokes the checker after a successful M1 parse, without changing the
syntax-only `niyahparse FILE` and `--ast` modes. Exit code 4 reports
a semantic error at a line:column; unsupported constructs fail closed.
Integer literals currently infer i64, not contextual byte literals.
The C and CLI suites cover scalar bindings, missing-return paths, forward and
recursive calls, exact arity/types, shadowing and rejection of void values.
The C test prints its executed positive and negative case counts.
Run `make -B verify-local` for M0/M1/M2 regressions.
GitHub Actions stays manual-only. No paid CI run is requested.

## CLI acceptance

`sh tests/check_cli_test.sh` covers valid scalar programs and calls, and
rejections for bad UTF-8, pointers, unknown identifiers, non-callable targets,
arity/type mismatches, void values, duplicate names, const writes, syntax
errors and stdout failure. This does not complete M2 or execute a call.

The checker initializer resets only live metadata and error coordinates;
unused symbol array entries remain uninitialised but are never read after
count=0. This prevents a freestanding build from accidentally depending
on compiler-emitted libc memset. The checker reuse test covers re-init.
