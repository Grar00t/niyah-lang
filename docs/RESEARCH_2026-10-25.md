# Engineering evidence: Arabic lexer and morphology (2026-10-25)

Scope: `niyah-lang` M0, Linux x86-64, freestanding C11.
This is a source review and design decision record, not an accuracy study.

## Observed code before hardening

- M0 code is a strict UTF-8 lexer for a small Arabic-keyword programming language.
- The morphology branch has candidate clitic/root/pattern segmentation, 10 seed verbs and no context model.
- The original source did not link src/morph.c; this was fixed previously.
- New local regression exposed malformed UTF-8 accepted *inside quoted strings and comments*.
- A direct /dev/full test exposed silent loss of failed stdout writes.
- Earlier tests revealed the UTF-8 prefix comparison read past a non-NUL-terminated test fixture.
- The GitHub Actions jobs failed before steps executed; the cause is not established.
  CI is now manual-only. Do not run hosted jobs unless separately authorized.

## Primary references and lessons (reviewed 2026-10-25)

| Reference | What it establishes | Decision for Niyah |
| --- | --- | --- |
| Unicode UAX #31 (https://www.unicode.org/reports/tr31/) | Identifier profiles and normalization choices must be explicit. | Preserve bytewise identifier identity for M0. Document risks; do not normalize inside morphology. |
| Unicode UTS #55 (https://www.unicode.org/reports/tr55/) | Source needs bidi-aware display and diagnostics; invisible marks and confusables create code-review hazards. | Recognize direction marks as existing trivia; document display limits. A full UTS #55 security audit is NOT implemented. |
| Unicode UTS #39 (https://www.unicode.org/reports/tr39/) | Confusability is contextual and not solved by naive Unicode scalar validity. | Do not claim the lexer prevents spoofing. Do not add hand-written confusable mappings. |
| Qalb (https://github.com/nasser/---) | An Arabic Scheme-like interpreter can provide a small, Arabic-native grammar and REPL. | Distinguish a language interpreter from a self-hosting native compiler; do not copy Qalb syntax or code. |
| Alif (https://github.com/alifcommunity/Alif) | Another Arabic general-purpose language exposes docs/examples and toolchain integration. | Keep Niyah's independent statically typed systems-language goal; no C++ transpiler dependency. |
| Kalimat (https://github.com/mobadarah/kalimat-lang) | Arabic educational language with a compiler and libraries; useful educational terminology. | Prefer small, executable examples and stable tokens; do not import its implementation. |
| CAMeL Morph (https://github.com/CAMeL-Lab/camel_morph) | Morphological analysis separates rule specs, lexicon and ambiguous analyses; project code MIT, data attribution CC BY 4.0. | Candidate lattice is honest; do not infer POS or contextual truth from one word. No external data copied. |
| CAMeL Tools packages (https://camel-tools.readthedocs.io/en/latest/reference/packages.html) | Software MIT, but individual morphology databases/disambiguators can be GPLv2. | Audit each data/model license before any future import. No automatic bundled corpus. |
| Qamous source list (https://qamous.org/sources) | A combined online lexicon contains materials under *different* licenses. | Do not scrape or vendor entries by assuming site-wide permission. |
| Tashaphyne (https://github.com/linuxscout/tashaphyne) | Existing GPL Arabic light stemmer includes segmentation and root extraction. | Learn from test taxonomy; avoid copying GPL implementation into MIT Niyah. |

## Rules frozen for M0

1. The lexer owns programming-language token boundaries, including T_IDENT and the
   eight Arabic keywords. Morphology never renames, splits or replaces those tokens.
2. The morphology layer emits a bounded list of possibilities and starts with an
   intact/raw candidate. No single candidate is declared a correct root.
3. The CLI rejects malformed UTF-8, including inside comments and string literals,
   and nonrecoverable read/write failures. File input >4 MiB is rejected.
4. Number glyph handling (Arabic-Indic, extended Arabic-Indic, ASCII), comma/semicolon
   equivalents, diacritics and zero-width direction marks preserve existing M0 behavior.
5. No third-party lexicon, model weights, package dependencies, trainable tokenizer
   or external assembler/linker was added.
6. All acceptance checks are local (make verify-local). The GitHub workflow
   is manual-only to avoid creating billable hosted jobs.

## Open correctness and research boundaries

- Column reporting counts Unicode scalar values, **not grapheme clusters**.
- Character normalization (NFC), mixed-script/confusable diagnostics and full
  UTS #55 bidi display protocols are NOT implemented.
- Heuristic morphology is not a substitute for curated Arabic dialect/MSA
  corpora; no linguistic precision/recall was measured.
- Whether this tokenization improves Arabic LLM quality, token cost or model
  generation is UNKNOWN. It would require a real token-to-ID vocabulary,
  held-out reference text, reversible decode tests and measured comparison.
- M1 parser/AST, type-checker and native compiler are NOT implemented.

## Repeatable evidence gates

- make test: golden tokens, lexer edge fixtures, CLI file guards, deterministic
  morphology fixtures and 5000 pseudo-random byte cases.
- make verify-local: previous checks plus GCC ASan/UBSan, ordinary Clang build
  and tests (Clang ASan runtime absent on Kali), readelf static ELF check.
- git diff --check must be clean before publishing; remote Git tree must equal
  the verified local tree. A hash proves bytes, not functional correctness.

Cost: no paid compute, external corpus downloads or SaaS testing were used.

## DeepSeek review triage (2026-10-25 follow-up)

The supplied review was treated as candidate findings and replayed locally,
not accepted as authority. A new full-stream regression test first failed
8 of 12 scenarios on published main b3b2b426. The observed defects were:
invalid UTF-8 string/comment token leakage, partial overflow tokenization,
CR-only line handling, and EOF-anchored unterminated-comment diagnostics.
The original tests only checked the first error token and missed recovery.
The separate test/CLI filter also dropped legitimate identifiers named
IDENT_MORPH; that case was reproduced before repair.

The smallest patch consumed invalid quoted/comment spans before reporting a
single error, consumed overflowing numeric literals to a digit boundary,
fixed CR/CRLF accounting, declared the syscall 'cc' clobber, and anchored
annotation filtering to structured output prefixes. Golden valid-token
output remained unchanged in make test.

Review items not treated as proven defects:
- ocp's 3-byte encoding is only applied to BMP Arabic root hypotheses.
- Hyphen is intentionally retained in --morph mode to support ASCII Al-.
- docs/grammar.ebnf already included 0x hexadecimal grammar before this patch;
  its maximal-munch/error behavior is now documented more precisely.

Primary sources:
- GCC Extended Asm (cc flags clobber): https://gcc.gnu.org/onlinedocs/gcc/Extended-Asm.html
- Unicode UAX #31 identifiers and normalization: https://www.unicode.org/reports/tr31/
- Unicode UAX #29 CRLF grapheme boundary: https://www.unicode.org/reports/tr29/

Verification: 13 full-stream deterministic scenarios and 5,000 seeded
lexical byte cases, plus morphology suite and GCC/Clang checks.
This does NOT establish compliance with all of UAX #31 or UAX #29.
