# M1 syntax parser + AST (2026-10-25)

Status (updated 2026-10-27): syntax parser and canonical AST
serialization working; M1 full milestone acceptance remains open.
Runs on Kali WSL. No third-party parser generator or Arabic lexicon imported.

## Commands

    make
    ./niyahparse examples/مرحبا.نيّة
    ./niyahparse --ast examples/مرحبا.نيّة
    make -B verify-local

The normal CLI prints OK M1 nodes=N for valid syntax. The AST option
prints a stable indented tree with node kind, source position and relevant
original token text. Errors report first token line/column, lexical or
syntactic cause and received token. CLI exits: 0 valid, 1 input/usage,
2 lexical/syntax error, 3 output failure. Inputs >4 MiB are rejected.

## AST invariant and grammar support

The lexer and morphology remain independent. Parser consumption uses
only original lex_next tokens, with no normalization or identifier rewrite.
Source buffer lifetime must exceed the AST lifetime. The parser uses a
fixed-capacity, 1-based u32 arena (0 = missing), not malloc or libc.
Each AstNode carries kind, original Token, and ordered first/last/next
child indices. The standalone CLI reserves 16,384 nodes and limits
nested parse frames to 128. Exhaustion returns an explicit error.

It recognizes functions, structs, fields, global/local var and const,
typed parameters, pointer and fixed-array types; blocks, if/else-if,
while, returns, assignments and expression statements; integer/string
literals, unary and precedence-ordered binary operators; calls, indexing
and field access. Binary operators associate to the left.

For a function, the child sequence is parameters, optional return type,
then block. For variables/constants, the children are declared type,
then optional initializer. For an if, the children are condition,
then block, then optional else node. Child order is source order.

## Verification

Local `make test` includes 30 positive / 30 negative syntax fixtures,
2 multi-error recovery cases, 8 canonical AST round-trips, 3,000 parser
byte inputs and 2,000 serialized-AST arbitrary-byte inputs. The AST checks
compare **ordered child structure**, not numeric arena IDs: original
parser allocation may place children before their parents, while the
deserializer uses preorder allocation. Canonical text round-trips, integer
values (including Arabic-Indic digits) and string escapes are checked.

Malformed serialized AST inputs (invalid names/operators, bad UTF-8,
invalid escapes, incomplete/trailing text), small buffers, cyclic in-memory
AST graphs and excessive nesting are rejected. AST structure/precedence,
arena exhaustion, deep-block/else-if guards, CLI diagnostics, oversized
input, failed writes and the human-readable golden AST remain covered.
Existing 5,000-case lexer and morphology fuzz fixtures and M0 goldens
continue to pass. Verify-local adds GCC ASan/UBSan and ordinary Clang
tests plus static ELF64 checks. Clang ASan runtime is unavailable in Kali.

During M1 integration a previous lexer typo was found: the token table
encoded the word ثاتب in place of ثابت. It was corrected and tests
verify ثابت is a keyword, while ثاتب and ثابتة remain identifiers.
A separate parser regression found unbounded else-if recursion; the
same depth limit now applies to that path.

## Not implemented

Syntax acceptance is NOT semantic correctness. No symbol table, type
checking, lvalue validation, missing-return detection, duplicate-symbol
checks or native code generation exist yet. Statement-boundary multi-error
synchronization is supported in limited cases (2 regression fixtures);
recovery is not exhaustive. Thirty positive and thirty negative **inline
fixtures** pass, but the planned full per-fixture golden dumps are not yet
present.

The internal `ast_serialize`/`ast_deserialize` format is a canonical
shape-and-payload round-trip: original token source locations are not
serialized. Token bytes and re-lexed numeric values survive; caller must
keep deserializer-owned payload bytes alive while using its AST. The
human-readable CLI `--ast` is NOT the serialized format, and neither
round-trip reproduces the original source. The deserializer does not
validate full AST grammar/parent-child semantics or perform M2 typing.

GitHub workflow remains manual-only (workflow_dispatch); local
verification does not incur hosted CI usage.
